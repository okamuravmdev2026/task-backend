# 📋 タスク管理システム (モックプロジェクト)

フロントエンド/バックエンド開発における、実務を意識した設計手法、主要なアンチパターンへの対策、および品質管理（自動テスト・CI/CD）を実証するためのポートフォリオです。仕様変更への追従として、実務的な項目（優先度・期限）の拡張や、フロントエンド側でのリアルタイム検索・絞り込み機能の追加も行っています。

---

## 🛠️ 技術スタック

### フロントエンド
- **Vue 3** (Composition API, `<script setup>` 構文)
- **Vuetify 3** (マテリアルデザインUIライブラリ)
- **Axios** (非同期HTTP通信ライブラリ)
- ※ 別リポジトリにて **React 19 (TypeScript / MUI)** バージョンも並行開発し、同一のバックエンドAPIに対するマルチフロントエンド接続を実証。

### バックエンド / DB
- **Java 21** (LTS)
- **Spring Boot 3.x** (Spring Web, Spring Data JPA, Validation, AOP)
- **H2 Database** (インメモリ、組み込み型DB)

### テスト & 信頼性
- **JUnit 5** / **Mockito** (単体テスト)
- **GitHub Actions** (CI/CD / 自動ビルド・自動テスト)

## 🎯 設計のこだわり ＆ 意識したポイント

採用担当者様へのアピールポイントとなる、実務レベルの設計思想を以下に網羅しています。

### 1. フロントエンド：UIライブラリの活用と高度なコンポーネント連携
企業の採用率が非常に高いUIライブラリ（Vue版: **Vuetify 3** / React版: **MUI**）を導入し、実務の業務システムに近いリッチなUI/UXを実現しました。
また、密結合なスパゲッティコード（アンチパターン）を防ぐため、**「スマートコンポーネント（親）」**と**「ダムコンポーネント（子）」**の役割を徹底して分離しています。
- **`TaskDashboard.vue` (親 / スマート)**: API通信、エラーハンドリング、全体の状態管理を担当。
- **`TaskForm.vue` / `TaskList.vue` (子 / ダム)**: 自身で状態を持たず、API通信も行わない。Propsによるデータの受け取りと、Emitsによる親へのイベント通知のみを行う再利用性の高いUI部品。
- **リアルタイム検索・絞り込み機能の最適化**:
  「タスク一覧」カードの直下、テーブルのすぐ上という最適なUI/UX位置へ配置。Vue版では **`computed`（算出プロパティ）** とコンポーネント間の **`v-model` 同期** を駆使し、React版では **`useState` と関数のProps渡し** を用いることで、双方のフレームワークの思想に最も適合した形で「親での状態統括・子でのUI表示」を両立させています。

### 2. バックエンド：Java最新仕様のキャッチアップと基本機能の網羅
- **Record型の採用**: 従来の泥臭いGetter/Setterを全廃し、DTO（`TaskRequestDto`, `TaskResponseDto`）に `Record` を採用することで、データの不変性（Immutable）の担保とコードの可読性向上を両立。
- **Stream API & ラムダ式**: コレクション操作においてfor文による手続き型の記述を排除し、Stream APIを用いた宣言的なプログラミングを徹底。
- **Optionalによるnull安全**: データの検索処理において、nullを直接返却したり握り潰したりせず、`Optional` を用いて安全にハンドリング。
- **Enum（列挙型）による型安全**: タスクのステータス（`TODO`/`DOING`/`DONE`）および優先度（`高`/`中`/`低`）をEnumで管理。アンチパターンである「数値やマジックナンバーでのDB管理」を徹底排除。

### 3. Webシステムの一般的なアンチパターンへの対策
実務における「システムの堅牢性」をアピールするため、以下の対策を実装しています。
- **画面が真っ白になる現象・生エラー露出の防止**: 
  `@RestControllerAdvice`（`GlobalExceptionHandler`）を導入し、バックエンドで発生した例外を一括補足。フロントエンドには一貫したJSON形式のエラーメッセージを返却し、セキュリティ脆弱性となるスタックトレースの露出を完全に排除。
- **フロント・バック両レイヤーでのバリデーション**:
  `jakarta.validation` を用いたサーバーサイドでの入力チェックを徹底。フロント側のチェック（HTML5バリデーション）の突破を許さない二重の防壁を構築。
- **生SQLの文字列結合による脆弱性の排除**:
  Spring Data JPA（またはプレースホルダー）を採用し、SQLインジェクション脆弱性を根本からシャットアウト。

### 4. 横断関心事の分離 (Spring AOP)
- 全APIの開始・終了、および例外発生時におけるパフォーマンスログおよびエラーログの出力を、`@Aspect` を用いて一括制御。各コントローラーに重複コードを記述するアンチパターンを防止しています。

### 5. 品質管理と自動化 (JUnit 5 & CI/CD)
- **Mockitoを使用した単体テスト**: `TaskService` のビジネスロジックに対して、仕様変更に追従した正常系（更新処理の成功）および異常系（存在しないID指定時の適切な例外スロー）を網羅したテストコードを JUnit 5 で記述。
- **GitHub ActionsによるCI環境**: リポジトリへの `push` または `Pull Request` 時に、GitHub上で自動的にJava環境を構築して GradleビルドおよびJUnitテストを実行。常に品質が担保されたコードのみがメインブランチにマージされる実務フローを再現。
